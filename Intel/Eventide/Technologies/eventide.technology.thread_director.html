The Problem With Software

A Scheduler Tick Is
An Eternity.

An OS scheduler wakes up roughly every millisecond. By the time it decides "move this thread to an efficiency core," the frame has already rendered, the packet has already landed, and a performance core burned power it never needed to spend. Software also can't see tiles — it counts cores, not which piece of silicon they live on. The Thread Director intercepts at the cache and dispatch level, where decisions land 1,000–10,000× faster than any scheduler tick — and where an entire GPU tile can be power-gated the instant work shifts away from it.

Continuous Decision Loop

Hardware Scheduling Pipeline

Thread Director runs a continuous, fully hardware-resident arbitration loop. Every step executes in silicon with deterministic latency — the OS is a partner, never a bottleneck.

01
Thread Classification

Monitor instruction mix, branch behavior, and memory access profiles for every runnable thread. Classify as latency-bound, throughput-bound, or memory-bound — per cache line, per frame, per packet.

02
LPNPU / GNA Prediction

The LPNPU co-pilot runs Intel's on-chip workload prediction model; the GNA continuously pre-filters low-rate telemetry streams for it at microwatt cost. Together they predict what's coming before it becomes runnable.

03
Thermal, Power & AFFINITY Check

Query per-core thermal headroom and the active AFFINITY™ contract. The same thread gets a different answer on battery than in the dock — and the check costs nanoseconds, not ticks.

04
Core Selection & Dispatch

Select the optimal core class, signal the OS with a dispatch hint, and pre-stage frequency, voltage, and cache state so the core is already at speed when the thread arrives.

05
Observe, Learn, Migrate

Watch execution in real time. If a thread's character changes — compute-bound turns I/O-bound — migrate it and remember the lesson. The prediction model updates from every observed run, so the chip gets smarter the longer you use it.

Seeing The Future

Prediction, Not Reaction.

A reactive scheduler is always one frame late. Thread Director front-runs the workload through four independent prediction channels — so cores are awake, scaled, and cache-warm the moment work lands.

GPU Channel
Frame Classification

Five 2D-only frames in a row? 2D Kanvas is pre-warmed and Druid stays dark. Complex shaders detected last frame? Druid DVFS is pre-scaled before the next command buffer arrives.

CPU Channel
Hint & History Learning

Apps and the OS can annotate threads ("latency-sensitive", "background"). Thread Director honors the hints, then refines them against observed behavior — a feedback loop between software intent and silicon reality.

Network Channel
Flow Analysis

SYN/ACK cadence flags interactive traffic; large TCP windows flag bulk transfers. Killer S1 packet steering happens in-fabric, with latency-sensitive flows routed to the fastest path.

Power Channel
Budget Awareness

Near the thermal ceiling, arbitration turns conservative before throttling can happen. Under an efficiency AFFINITY, wake requests for big cores are simply denied — politely, in hardware.

AI-Assisted Dispatch

LPNPU Co-Pilot Mode

Why a scheduler needs an NPU

Eventide has a hardware accelerator for everything — 3D on Druid and Elementalist, 2D on Kanvas, media on MFX, imaging on IPU and BionzXR, audio on Klangkerne, AI on HNPU. That's the whole point of the tile architecture. But it creates a scheduling problem no OS was built for: every task now has half a dozen valid homes.

That's why the Thread Director was designed from day one to work with the LPNPU (88 TOPS, <1.4W, always-on) and the GNA. The LPNPU runs Intel's on-chip workload prediction model, classifying upcoming instruction patterns and feeding pre-routing signals to the Thread Director. The GNA handles continuous, microwatt-class signal classification — telemetry, audio events, sensor streams — so prediction never sleeps even when the LPNPU does.

The result is proactive core preparation: frequency scaling, voltage adjustment, and cache pre-warming before threads become runnable — and a model that adapts to how you use the machine, no tuning required.

Anyone can clamp a TDP and call it a power profile. AFFINITY™ is different: it optimizes for how the machine feels, not just what it draws.
